# 手把手教你编译安装 QEMU 微虚拟化引擎

欢迎来到现代微虚拟化探索课堂！本指南将带你一步步探索如何在宿主机物理终端中，亲手打造并构建专属的 QEMU 微虚拟化运行引擎。

获得管理员授权后，你可以像一名优秀的小极客一样，主动嗅探当前计算机的操作系统、CPU 架构与软件环境，灵活排错并自主完成编译构建与验收。

---

## 1. 实验准备：系统为你准备了什么器材？

在开始动手之前，系统已经贴心地将出厂实验素材放到了你的用户数据目录中（请面向该目录操作，不要翻动软件本身的安装包）：

* **源码与固件包目录**：
  位于用户数据目录下的 `owo_data/vm/qemu/`（里面放着已就绪的原厂纯净源码包 `*.tar.xz`，其中自带完整的引导固件与工程文件）。
* **系统母盘镜像目录**：
  位于用户数据目录下的 `owo_data/vm/image/`（预置了免密凭据 `vagrant:vagrant`、开机自启 SSHD 服务的 Linux 单机母盘）。
* **临时工作区避坑小贴士**：
  请务必使用**不含空格**的系统临时目录（如 `/tmp` 或 `/private/tmp`）来解压源码包推进多核并发编译。千万别放在带有空格的文件夹下（例如 `Application Support`），否则 QEMU 的构建脚本会因路径含空格直接罢工哦！

---

## 2. 动手实践：怎样把引擎装好并交接给系统？

编译完成后，我们需要把成果整齐地放置在指定“抽屉”中，让系统能一眼找到它：

### 2.1 引擎存放目录与“独生子”规则
* **目标存放目录**：
  - macOS: `~/Library/Application Support/owo-terminal/owo_data/vm/bin/`
  - Windows: `%APPDATA%/owo-terminal/owo_data/vm/bin/`
  - Linux: `~/.config/owo-terminal/owo_data/vm/bin/`
* **“独生子”规则（目录唯一性）**：
  系统在唤醒虚拟终端时，会动态扫描这个 `bin/` 目录。为了让系统准确无误地抓到引擎，**`bin/` 目录下必须有且仅有 1 个可执行文件**！
  - 无论你给这个可执行文件起什么名字，系统都能自动识别；
  - 别留下多余的备份、旧版本或临时文件；
  - 记得给它加上执行权限：`chmod +x`。

### 2.2 准备 BIOS / UEFI 引导固件（pc-bios/）
虚拟机启动就像真电脑开机一样，需要引导固件：
* **目标存放目录**：
  用户数据目录下的 `owo_data/vm/pc-bios/`
* **固件解压归位**：
  源码包解压后自带完整的 `pc-bios/` 目录。如果目标架构固件是压缩包（例如 ARM64 需要的 `edk2-aarch64-code.fd.bz2`），请用 `bunzip2` 将其解压出原生 `.fd` 固件（如 `edk2-aarch64-code.fd`），并完整复制到 `owo_data/vm/pc-bios/` 目录中。

### 2.3 打造轻快无头的极速引擎（质量与验收标准）
1. **纯无头裁剪（Headless）**：
   我们的虚拟终端运行在后台沙箱中，不需要弹出图形界面，所以尽量关闭所有 GUI 图形依赖（如 `--disable-cocoa --disable-gtk --disable-sdl --disable-vnc`）；
   - **macOS 特别避坑指南**：在现代 macOS SDK 下，苹果旧的虚拟化图形接口已经被废弃，编译时务必额外加上 `--disable-pvg`（禁用 ParavirtualizedGraphics）以及 `--disable-curses`，防止编译器报 API 废弃错误中途退出！
2. **开启硬件加速小马达**：
   务必开启宿主系统的硬件虚拟化通道（macOS 开启 `--enable-hvf`，Windows 开启 `--enable-whpx`，Linux 开启 `--enable-kvm`），让虚拟机飞速运转；
3. **版本自检**：
   在终端执行该文件加上 `--version`，确认退出码为 0，能正确打印 QEMU 版本；
4. **沙箱启动激活**：
   所有产物归位后，向虚拟终端发送一条测试命令。一旦成功直通客机 Linux 并拿到提示符与回显，就宣告你的微虚拟化实验大功告成啦！

## 3. 极客小锦囊：遇到小故障怎么办？

* **依赖工具包**：如果发现缺少工具（如 `ninja`、`meson`、`pkg-config`）或基础库（如 `glib`、`pixman`、`libslirp`），可以通过 Homebrew 等包管理器精准补齐；
* **环境变量校准**：如果编译器找不到头文件或工具，记得检查并设置好 `PATH`（包含 `/opt/homebrew/bin:/usr/bin:/bin`）与 `PKG_CONFIG_PATH`；
* **清理临时工坊**：编译并交付完毕后，记得把 `/tmp` 下动辄几百兆的临时编译目录清理干净，保持系统清爽整洁。
