1. 少即是多，一切皆是Box

  Box组件是基本的样式盒子（请务必阅读Box.js），它同时提供了所有组件的基本样式规范
  Tag组件是Box组件的继承，它提供了小标签的样式

  Box的基本样式类似下面这些（不一定，这是我常用的设计样式）
  基本间距单位 建议1rem 小间距0.5rem
  圆角 建议3rem
  边框线 无边框线
  背景颜色 使用getColor(颜色名).back
  文字颜色 使用getColor(颜色名).front
  -----
  宽度 不设置，默认是auto
  高度 不设置，根据内容撑开
  字号 不设置，全局继承 1.5rem = 15px
  行高 不设置，浏览器默认
  字重 不设置，默认

  你可以直接使用Box组件，但是有时候Box组件会过于繁重，你也可以使用普通div+遵照上面的基本样式，来叠加组件

  Box组件最常见的使用例子是作为按钮,设置 isBtn:true
  Tag组件同理，作为小按钮

  Box组件同时还作为任何东西的容器，所以你可以

  m Box,[
    #我要放置的内容
    m Box,[

    ]
  ]
  因为Box自带简单边距，所以可以快速创建出视觉上感觉还不错的东西
  但是同时我们也要注意到 两个Box叠加，那边距实际上是2rem
  但是我设计原则里，为了最简开发，通常会忽略这个。我不会编辑额外的样式，来消除它，或者我更常用0.5rem来叠加。因为1rem可能有点宽

  但是很多情况下，默认的样式并不合理，我们会叠加样式
  最常见的常见就是使用flex

  m Box,
    style:
      display:"flex"
      justifyContent:"center"
      alignItems:"center"
  ,[]

  注意Tag覆盖样式使用styleExt
  m Tag,
    styleExt:
  ,[]

  Box还有其他用途，比如作为文本框

  Input = new Box()

  m Input,
    tagName:"input[type=text]"
  
  获取输入内容 Input.data.value

  或者作为开关
  m Input,
    isSwitch:true
    color:"main"
  
  获取开关状态，依然是 Input.data.value

3. 虽然绝大多数情况下，不建议设置字号，但是，完全一样的字号反而会产生视觉干扰
所以下面是一个推荐
级别 (Role)	建议字号 (rem / px)	适用场景 (Usage)	视觉心智 (Affordance)
L1 (大标题 / Display)	2.2rem (22px)	窗口主标题（如“设置中心”）、看板大数字	最强视觉焦点，一页通常仅 1-2 处
L2 (大类标题 / Title)	1.8rem (18px)	侧边栏一级类目（“全局”）、卡片大组标题	引导大板块划分
L3 (子级标题 / Subtitle)	1.6rem (16px)	顶部三级子菜单（“大模型”）、分组子标题	引导局部聚焦
Body (正文基准 / Base)	1.5rem (15px)	全局默认继承！输入框、按钮、正文文字、列表项	占据界面 80% 以上，最耐读的基准
Caption (辅助注释 / Small)	1.2rem (12px)	字段下方描述说明（description）、时间戳、模型ID副标	次要辅助信息，弱化存在感

优先使用双引号
例如：
m "",
  style:
    color:"#555555ee5"
    background:"#ffdb66"
非必要不要使用字符小图标，而应该考虑使用项目里iconPark

非必要不要修改行高

统一使用rem单位，计算类可以考虑px单位

非必要避免使用border-box
优先使用自适应布局，必须适配移动端【重要】

,[
  m "span",

      color:"#555555ee"
      margin:"2rem 1rem" #使用margin撑开文字
  ,"我是按钮"
]

padding和inline-block，对于按钮这种组件或者是排版文字的父容器，设置页边距是合理，所以也不是完全不能用
但是inline-block经常有奇怪问题，最好不要使用行内相关的布局来布局非段落文本的东西
虽然我也会用就是了
不要使用backdropfilter blur的高斯模糊，影响性能，如果要使用模糊效果，优先采用背景处模糊一个纯色的圆或者椭圆来实现朦胧的背景效果

## 前端代码风格与模块化指南

为了保持代码的高度可读性、一致性以及与系统架构的完美契合，所有 App 前端开发必须遵循以下准则：

交代：
> 1不使用任何cssClass，使用行内style，不写任何css类名。 2所有的对象都要换行 3mithril的第一个参数如果是div，应该简写成空字符串。3如果一个前端事件处理函数没有被复用，应该直接写在事件里面，而不应该外置
> 减少临时变量和中间变量的使用。直接使用嵌入式写法。例如，let a = 12 ; let b = 5; let c = a+b;console.log(c)这还是错误的写的，你应该直接console.log(a+b)
> 前端组件注意：1 每个模块必须是合法的mitrhil函数组件，不能仿照入口点frontend.js的写法。参数传递使用mithril的组件传参方式传递 所有尺寸单位统一使用rem 1rem 约等于 10px
> 所有的异步处理必须用try catch包裹并输出错误，不能省略任何错误的输出

### 6.1 极致垂直化格式 (Vertical Formatting)
- **对象属性换行**：对象（尤其是 `style` 和配置对象）的每一个属性必须独占一行。
- **函数参数换行**：`m()` 函数的参数（tag, attrs, children）必须独占一行。
- **示例**：
  ```javascript
  m("",
    {
      style: {
        display: "flex",
        flexDirection: "column",
        padding: "20px"
      }
    },
    [ ... ]
  )
  ```

### 6.2 零 CSS 类名原则 (Zero CSS Class)
- **严禁使用** `class` 或 `cssClass`。
- **必须使用** 行内样式 (`style`)。这确保了组件的样式完全自包含，不依赖外部 CSS 文件。
- **颜色调用**：统一使用注入的 `getColor(name).back/front` 来获取主题颜色。
其中同一个颜色下，back为背景色,front为背景色对应的文字色/前景色。
【重要】禁止发生混合使用不同颜色的背景色和前景色混搭，颜色搭配系统已经配好了。如果你的背景色是getColor("red").back，那前景色/文字色必须使用getColor("red").front，不能使用其它颜色
- **字体和字号** 不要指定任何字体，通常不需要指定字号，特殊内容可以少量指定字号

### 6.3 嵌入式写法 (Inline Expressions)
- **减少中间变量**：避免定义只使用一次的临时变量。
- **逻辑直接嵌入**：将逻辑判断、字符串拼接、数组映射直接写在 `m()` 的参数中。
- **示例**：
  - ❌ `let isDir = name.endsWith('/'); m("", isDir ? "📁" : "📄")`
  - ✅ `m("", name.endsWith('/') ? "📁" : "📄")`

### 6.4 语义化简写
- **Mithril 简写**：当第一个参数是 `div` 时，必须简写为空字符串 `m("", ...)`。
